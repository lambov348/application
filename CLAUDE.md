# MöbelStock24 — система заказов, работников и зарплаты

Этот файл — главный источник требований (сокращённое ТЗ). Читай его в начале каждой сессии.
Владелец проекта — не программист: объясняй простыми словами, спрашивай перед установкой программ и перед любыми действиями, которые что-то удаляют.

## Что строим
- Веб-админка для владельца (компьютер): заказы, клиенты, работники, часы, зарплата, отчёты.
- Приложение для работников (телефон): только свои задания, смена старт/стоп, чек-лист, фото до/после, файлы, замечания.
- Сначала PWA (иконка на главном экране), позже упаковка через Capacitor в App Store и Google Play — не принимать решений, которые этому мешают.
- Три языка с первого дня: русский, английский, немецкий.
- Несколько фирм в одной базе (позже систему будут продавать другим фирмам).

## Стек (не менять без согласия владельца)
Laravel 11+, PHP 8.3, Vue 3 + Inertia.js, Tailwind CSS, vue-i18n, PostgreSQL 16, Redis, Pest (тесты).
Сервер позже: VPS в Германии, Nginx + HTTPS. Сейчас разработка локально.

## Роли и доступ
- Владелец: всё.
- Работник: видит только назначенные ему заказы; никогда не видит суммы заказов, прибыль, ставки коллег, чужих клиентов.
- Права проверяются на сервере (Policies) на каждом запросе, не скрытием кнопок.
- Регистрации нет: аккаунты создаёт владелец. Первый вход — работник задаёт свой пароль.

## Модули
1. Заказы: номер (2026-0412), клиент, адрес, этаж/лифт, парковка, описание, термин (дата, начало, конец), исполнители, стоимость, материал, источник, номер Angebot, статус, оплата клиентом.
   Статусы: Новый → Запланирован → Подтверждён (работник принял) → В работе → Выполнен → Оплачен; из Нового/Запланированного → Отклонён (с причиной).
   Нельзя закрыть без минимум 2 фото «после». Любое изменение → order_events.
2. Клиенты: имя, телефон, email, язык документов, несколько адресов, история заказов. Быстрый поиск.
3. Работники: имя, телефон, логин, язык интерфейса, модель оплаты, активен/уволен (уволенный сразу теряет доступ, история остаётся).
4. Смены и часы: старт/стоп по времени сервера; внутри смены — часы по каждому заказу; незакрытая смена: пуш в 22:00, автозакрытие в 23:59 с пометкой «проверить». Правка часов — только владелец, с причиной, в audit_log.
5. Зарплата: модели hourly / per_job / mixed / fixed; ставки с датой действия.
   К выплате = часы × ставка_час + выезды × ставка_выезд + фикс + премии − вычеты − авансы.
   «Закрыть месяц» сохраняет итог в payroll_results; закрытый месяц не пересчитывается.
6. Дашборд и отчёты: выручка месяц/год, заказы по статусам, средний чек, неоплаченные счета, часы, зарплаты, диаграмма 12 месяцев; отчёты за период; экспорт PDF и Excel/CSV.
7. Файлы и фото: хранятся на сервере, отдаются только через систему по временной ссылке; загрузка с камеры пачкой, повтор при обрыве; превью ~2000 px.
8. Уведомления (MVP): пуш (Web Push; позже нативные). Календарь: личная ICS-ссылка. WhatsApp-бот — этап 2.

## Языки
- Все строки интерфейса только в файлах переводов ru / en / de, ни одной строки в коде.
- users.locale; при первом входе — язык браузера; переключение в профиле одним нажатием.
- Даты, числа и деньги в формате языка: 1.480,00 € (DE), €1,480.00 (EN), 1 480,00 € (RU).
- Пуши, письма, PDF — на языке получателя; документы клиенту — на языке клиента (по умолчанию de).
- Тест: во всех трёх файлах одинаковый набор ключей, пустых строк нет.

## База данных (PostgreSQL)
Каждая таблица с данными фирмы имеет company_id; ограничение по фирме — global scope. Деньги в центах (integer). Время в UTC, показ Europe/Berlin. Удаление — soft delete.
- companies: id, name, default_locale, timezone, plan, is_active
- users: id, company_id, role, name, login, password_hash, phone, locale, ics_token, is_active, last_login_at
- push_subscriptions: user_id, platform (web/ios/android), token
- pay_rates: user_id, model, hourly_cents, per_job_cents, monthly_cents, valid_from, valid_to
- clients: id, company_id, name, phone, email, locale, notes
- addresses: client_id, street, zip, city, floor, has_elevator, parking_note
- orders: id, company_id, number, client_id, address_id, title, description, status, date, start_time, end_time, price_cents, material_cents, source, offer_no, reject_reason, payment_status, paid_at, completed_at
- order_assignments: order_id, user_id, accepted_at, declined_at
- checklist_items: order_id, text, position, done_by, done_at
- order_files: order_id, uploaded_by, kind (before/after/plan/document), path, thumb_path, size_bytes, mime
- order_comments: order_id, user_id, text
- order_events: order_id, user_id, type, data (json)
- shifts: user_id, started_at, ended_at, auto_closed, needs_review
- work_logs: shift_id, order_id, user_id, started_at, ended_at
- payroll_periods: company_id, year, month, status, closed_at, closed_by
- payroll_adjustments: period_id, user_id, type (bonus/deduction/advance), amount_cents, reason, created_by
- payroll_results: period_id, user_id, hours, trips, gross_cents, payable_cents, details (json)
- notifications: user_id, channel (push/whatsapp), type, data, locale, status, attempts, sent_at, error
- audit_log: company_id, user_id, entity, entity_id, action, before, after, reason
- settings: company_id, key, value

## Этапы
0. Локальная среда (сейчас) / позже сервер.
1. Основа: вход, роли, фирма, работники, клиенты, заказы; три языка.
2. Кабинет работника: задания, смены, чек-лист, фото, файлы, замечания; установка PWA.
3. Пуш-уведомления и календарь ICS.
4. Деньги: ставки, часы, зарплата, авансы, закрытие месяца.
5. Дашборд и отчёты, экспорт.
6. Приложение в магазинах (Capacitor).
7. Этап 2: WhatsApp-бот, подключение других фирм и подписка, Google Calendar.

## Правила работы
1. Перед кодом каждого этапа — короткий план (папки, миграции, модели, маршруты). Жди «ок».
2. Маленькие шаги. После каждого — команды запуска и что проверить руками (простыми словами).
3. Тесты Pest: доступы, изоляция фирм, расчёты зарплаты, ключи переводов. «Готово» — только когда тесты зелёные.
4. Не выдумывай требования. Нет в этом файле — задай один короткий вопрос.
5. Секреты только в .env, приложи .env.example. Не коммить .env.
6. Используй git: коммит после каждого завершённого шага с понятным сообщением.
7. Бухгалтерия: система считает внутреннюю зарплату для управления; официальная Lohnabrechnung — у Steuerberater, система только выгружает данные.
