# MöbelStock24 — внутренняя платформа

Реализация по `TZ_MobelStock24_Platform.md` (в корне репозитория).
Текущее состояние: **Этап 0, куски 1–3 из 10** — каркас, база, миграции, вход с ролями и 2FA, управление сотрудниками, установка на телефон.

Старое приложение (публичная форма заявок) живёт в корне репозитория и не
затрагивается.

---

## Запуск

### Через Docker (рекомендуется)

```bash
cd apps/platform
cp .env.example .env

# Секреты. Без них приложение намеренно не стартует.
echo "AUTH_SECRET=\"$(openssl rand -base64 32)\""      >> .env
echo "ENCRYPTION_KEY=\"$(openssl rand -base64 32)\""   >> .env
echo "POSTGRES_PASSWORD=\"$(openssl rand -hex 16)\""   >> .env

docker compose up -d postgres redis
docker compose run --rm app npx prisma migrate deploy
docker compose up -d app
```

Открыть http://localhost:3000

### Первый вход

В базе нет ни одного пользователя и нет сидов с выдуманными людьми. Первого
владельца создаёт скрипт — он спросит имя, email, роль и пароль:

```bash
docker compose run --rm app npm run create-user
# без Docker:  npm run create-user
```

Роль `INHABER` не пускает в систему без второго фактора (глава 4 ТЗ). При
первом входе форма предложит перейти на `/login/2fa-einrichten`: там появится
QR-код для Google Authenticator, Aegis, 1Password или подобного приложения,
а после подтверждения — десять кодов восстановления. **Коды показываются
ровно один раз**, сохраните их.

Дальше сотрудников заводит владелец в разделе «Benutzer» — командная строка
больше не нужна.

### Без Docker

Нужен PostgreSQL 16. В `.env` замените в `DATABASE_URL` хост `postgres` на `localhost`.

```bash
cd apps/platform
npm install
npx prisma migrate dev
npm run dev
```

Проверяют то, что не ловится юнит-тестами: установку на телефон, вход без
JavaScript, разделение доступа по ролям и скорость.

```bash
npm run build && npm start          # в одном окне

# в другом; учётные данные берутся из окружения и в репозиторий не попадают

SMOKE_MONTEUR="max@firma.de:пароль" \
SMOKE_DISPONENT="petra@firma.de:пароль" \
```

Без переменных с учётными данными проверки входа пропускаются, остальные
выполняются.

## Отклонения от главы 7 ТЗ

| Что | Как в ТЗ | Как сделано | Почему |
|---|---|---|---|
| `leads` и `deals` | две таблицы | одна `Deal` | Канбан главы 5.2 — одна лента колонок на обе стадии. Две таблицы дали бы два поля `status` и вопрос, какое из них на карточке. |
| Деньги | тип не указан | `Int`, центы | Требование заказчика. Брутто не хранится: вычисляется из нетто и ставки, иначе хранимая копия разойдётся с расчётом. В `Offer` суммы заморожены снимком — это документ. |
| Ставка НДС | `vat_rate` | `vatRateBp`, базисные пункты | 19 % → `1900`. Целое число вместо дроби. |
| `price_approved` | `bool` | + `priceApprovedAt`, `priceApprovedById` | Через полгода нужно уметь показать, кто и когда одобрил цену. |
| Назначение на выезд | только `team_id` | + `AppointmentAssignee` | Правило «Monteur видит только свои заказы» становится строкой в запросе, а не вычислением через членство в бригаде. |
| Статусы выезда | два разных набора (5.3 и 5.6) | объединение, 6 значений | В 5.3 отсутствует `ANGEKOMMEN`. |
| `addresses.lat/lng` | есть | убрано | Предупреждение «мало времени на переезд» без геокодинга не посчитать, а геокодинг — внешний сервис и отдельный вопрос по DSGVO. Вместо него `Settings.travelBufferMinutes`. Вернём в Этапе 2. |
| `activity_log` | таблица | + поле `ip`, только вставка | IP нужен для фиксации согласия с Angebot (глава 5.4). Неизменяемость держит триггер в базе. |
| Даты | не указано | `timestamptz` везде | Prisma по умолчанию создаёт `timestamp without time zone`, где смещение не хранится, и любой внешний инструмент истолкует время по своему часовому поясу. |
| Сессии Auth.js | таблицы адаптера | JWT + `User.sessionsValidFrom` | Auth.js не поддерживает сессии в БД вместе со входом по паролю. Отметка времени даёт отзыв сессий и мгновенное применение блокировки. Таблицы `Account`/`Session` не создаются: при входе только по паролю они не используются. |

## Что держит сама база, а не только код

Миграция `db_guards`. Проверки в приложении можно обойти сырым SQL или скриптом
миграции данных — эти нельзя:

- журнал действий: `UPDATE` и `DELETE` отбиваются триггером;
- `Settings`: ровно одна строка (`CHECK id = 1`);
- **правило 9.7**: сделка в статусе `VERLOREN` обязана иметь причину;
- выезд не может кончаться раньше, чем начался;
- ставка НДС в пределах 0–100 %, версия Angebot ≥ 1.

## Предупреждение на Этап 2: нумерация счетов

Номер заявки `Deal.number` — последовательность Postgres, и в ней **бывают
пропуски**: откатившаяся транзакция значение не возвращает. Для заявок это
безразлично.

Для счетов — нет. Правило 9.5 запрещает пропуски в нумерации, поэтому номер
Rechnung обязан выдаваться строкой-счётчиком в `Settings` под `SELECT ... FOR
UPDATE` в той же транзакции, что и создание счёта. Последовательность для
счетов использовать нельзя.

## Установка на телефон

Приложение ставится **по ссылке, без App Store и Google Play** — так решено
главой 5.6 ТЗ, и это не компромисс:

- Apple отклоняет приложения, которые являются обёрткой вокруг сайта
  (правило 4.2 «Minimum Functionality»); внутренний инструмент для пяти
  человек через магазин не проходит;
- аккаунты разработчика стоят 99 $ в год у Apple и 25 $ разово у Google;
- каждое обновление проходит ревью по несколько дней, а здесь исправление
  доезжает до телефона монтажника сразу.

Внешне разницы нет: значок на домашнем экране, запуск на весь экран без
адресной строки браузера.

**Android, Chrome.** Открыть адрес платформы → меню (три точки) →
«Установить приложение».

**iPhone, Safari.** Открыть адрес платформы → «Поделиться» →
«На экран "Домой"». Обязательно Safari: другие браузеры на iOS этого не умеют.

Значки лежат в `public/icons` и сейчас являются **временным геометрическим
знаком**, а не логотипом фирмы. Когда появится настоящий логотип, положите
PNG с теми же именами или поправьте `scripts/generate-icons.ts` и запустите
`npm run icons`.

## Два входа

| Кто | Адрес | Вид |
|---|---|---|
| Офис (владелец, диспетчер) | `/login` | светлый экран для монитора |
| Бригада | `/m/anmelden` | тёмный экран во весь телефон |

Проверка одна и та же, различается только оформление и то, куда человек
попадает после входа. С каждого экрана есть ссылка на второй — на случай,
если открыли не тот.

Вход бригады **работает с выключенным JavaScript**: Next отдаёт форме
серверного действия обычную отправку методом POST. В подвале, где скрипты
могут не догрузиться, монтажник всё равно войдёт.

## Скорость

Замеры на сборке продакшена (`npm run smoke`):

| Показатель | Значение |
|---|---|
| Ответ сервера, медиана | 15 мс |
| Первая отрисовка | 72 мс |
| Первый заход, всего | 153 КБ |
| Повторный заход | 0 КБ — всё из кэша service worker |

Из чего состоит первый заход: 116 КБ скриптов (рантайм Next и React,
неустраним без смены архитектуры), 31 КБ шрифтов, 6 КБ прочего.

Шрифты были 153 КБ на 12 файлах: грузились два семейства, четыре
насыщенности и набор символов latin-ext. Узкое начертание из макета не
использовалось ни в одном компоненте, насыщенность 500 тоже, а latin-ext
нужен для восточноевропейских языков, которых у нас нет — немецкие ä ö ü ß
входят в основной набор. Осталось два файла и 31 КБ. Для телефона на слабой
связи каждый лишний файл шрифта — отдельное обращение к серверу.

## Что кэшируется, а что нет

Телефон монтажника могут потерять или передать другому человеку, поэтому
service worker (`public/sw.js`) устроен строго:

- **кэшируются** файлы сборки с хешем в имени, значки и страница «нет связи»;
- **никогда не кэшируются** страницы с данными, ответы Auth.js и всё, что
  не является запросом GET.

Адреса и телефоны клиентов не остаются в кэше браузера после выхода
из системы. Очередь отправки фотографий из офлайна появится вместе с
кабинетом монтажника (кусок 9) — она требует IndexedDB.

## Вход и права

| Что | Как сделано |
|---|---|
| Пароли | scrypt из `node:crypto`, параметры записаны в самой строке хеша — их можно усилить позже, не ломая существующие пароли |
| Второй фактор | TOTP (RFC 6238), совместим с Google Authenticator и аналогами. Секрет в базе зашифрован AES-256-GCM ключом `ENCRYPTION_KEY` |
| Коды восстановления | десять штук, в базе только хеши, каждый срабатывает один раз |
| Сессии | JWT, срок из `SESSION_MAX_AGE_SECONDS` (по умолчанию 8 часов) |
| Отзыв сессий | `User.sessionsValidFrom`. Отключение сотрудника, смена роли и смена пароля выбрасывают его немедленно, а не через 8 часов |
| Перебор паролей | не более 8 неудачных попыток на email за 15 минут |
| Журнал | вход, неудачный вход, использование кода восстановления, все изменения сотрудников |

Проверка роли идёт в двух местах, и это не дублирование:

- **middleware** отсекает по адресу, опираясь только на токен (базы в edge-среде
  нет) — быстро и грубо;
- **`requireUser()` / `requireRole()`** читают состояние из базы на каждом
  обращении — это авторитетная проверка. Токен отключённого сотрудника
  middleware пропустил бы до истечения срока.

Скрытые пункты меню защитой не считаются.

## Известные решения, требующие подтверждения

- **Шрифт.** У Barlow из макета нет кириллического начертания. Немецкий
  интерфейс выглядит как в макете, русский рисуется следующим шрифтом стека.
- **Auth.js v5 в статусе beta.** Стабильная ветка v4 работает только со старым
  Pages Router. Версия зафиксирована точно, без `^`.
- **Prisma 7.10.0** закреплена явно: в теге `latest` у npm сейчас стоит
  release candidate 8.x.
- **Предупреждение при сборке** `CompressionStream ... not supported in the Edge
  Runtime` из библиотеки `jose` — безобидное: этот путь используется только для
  сжатых токенов, которых Auth.js не выпускает.

## Сотрудников не удаляют

Внешний ключ `ActivityLog.userId` объявлен с `onDelete: Restrict`. Удалить
сотрудника, у которого есть записи в журнале, база не даст — и это намеренно:
журнал действий не должен терять автора. Вместо удаления сотрудника отключают
(`active = false`), а по требованию DSGVO его данные обезличиваются; записи
журнала продолжают ссылаться на обезличенную учётную запись.

Без `Restrict` попытка удаления запускала бы `SET NULL` на журнале, то есть
`UPDATE`, который запрещён триггером неизменяемости, — и падала бы невнятной
ошибкой из глубины базы.
