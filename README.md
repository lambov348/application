# MöbelStock24 — CRM + управление заявками

Веб-приложение для монтажной компании. Состоит из двух частей:

1. **CRM в стиле amoCRM (`/crm`)** — главный рабочий инструмент владельца:
   визуальная воронка-канбан со сделками (перетаскивание между этапами),
   быстрые карточки клиентов и сделок, задачи с напоминаниями, история
   общения (в т.ч. вставка сообщений WhatsApp), экран «Сегодня».
2. **Приём заявок и исполнители** — публичная форма заявки без регистрации,
   кабинеты админа и исполнителя (в духе TaskRabbit).

## CRM (amoCRM-style) — как пользоваться

- **Вход:** `admin@moebelstock24.de` / `admin123` → сразу попадаете в воронку `/crm`.
- **Воронка `/crm`:** 10 этапов (Новая заявка → … → Выполнено/оплата, Отказ).
  Перетаскивайте карточки мышкой между колонками. Вверху — переключатель
  направлений: **MöbelStock24 / ReinigungBerlin24 / Renovierung Berlin 24**.
- **Карточка сделки:** тип услуги, суммы, даты монтажа, команда, оплата,
  условия объекта, правило парковки, история общения, задачи, WhatsApp-клик.
- **Автоматизации:** при смене этапа задача создаётся сама — «Позвонить»,
  «Написать после Angebot», «Напомнить о парковке», «Проверить оплату» и т.д.
  (см. `src/lib/crm.ts` → `STAGE_AUTOMATIONS`).
- **Экран «Сегодня» `/crm/today`:** работы сегодня, задачи, не оплачено,
  кто ждёт ответа — всё, что нужно владельцу утром.
- Структура полей и этапов настраивается в одном файле — `src/lib/crm.ts`.

## Возможности

- **Клиент (без регистрации):** витрина категорий услуг, форма заявки с
  фото, экран «Заявка принята» с номером и отслеживание статуса по номеру.
- **Админ:** дашборд со сводкой и фильтрами по статусу, карточка заявки со
  всеми данными и историей, назначение исполнителя, ручная смена статуса,
  внутренние заметки, управление исполнителями (добавить / отключить, задать
  логин и пароль).
- **Исполнитель:** видит **только свои** задачи, меняет статус
  «Принять в работе» → «В работе» → «Выполнено», добавляет комментарий и фото
  результата. Не имеет доступа к чужим задачам и админ-функциям.

Права проверяются **на сервере** (в каждом Server Action и в layout'ах кабинетов),
а не только в интерфейсе.

## Стек

- **Next.js 15** (App Router) + **TypeScript** + **Tailwind CSS**
- **Prisma** + **SQLite** (легко переключить на PostgreSQL — см. ниже)
- Аутентификация: подписанные JWT-куки (`jose`), пароли хэшируются `bcryptjs`
- Загрузка фото — локальное хранилище (`./storage/uploads`), отдаётся через
  route-handler `/uploads/[name]` (работает и в dev, и в production)

## Запуск

Требуется **Node.js 18+** (проверено на Node 22).

```bash
# 1. Установить зависимости
npm install

# 2. Сгенерировать клиент, создать БД и заполнить тестовыми данными
npm run setup

# 3. Запустить в режиме разработки
npm run dev
```

Приложение: <http://localhost:3000>

### Продакшен-сборка

```bash
npm run build
npm run start
```

## Тестовые логины

Вход для сотрудников — по кнопке «Вход для сотрудников» или на `/login`.
Клиенту вход не нужен.

| Роль          | Email                       | Пароль      |
| ------------- | --------------------------- | ----------- |
| Администратор | `admin@moebelstock24.de`    | `admin123`  |
| Исполнитель   | `anna@moebelstock24.de`     | `worker123` |
| Исполнитель   | `boris@moebelstock24.de`    | `worker123` |

Тестовые данные: 5 заявок в разных статусах (новая, назначена, в работе,
выполнена, отменена).

## Как проверить, что всё работает

1. Откройте <http://localhost:3000> — витрина услуг. Нажмите категорию или
   «Оставить заявку».
2. Заполните форму (можно приложить фото) и отправьте — увидите экран
   **«Заявка принята»** с номером.
3. Скопируйте номер, откройте **«Отследить заявку»** и введите его — статус
   **«Новая»**.
4. Войдите как **админ** (`admin@moebelstock24.de` / `admin123`). На дашборде
   видна новая заявка. Откройте её карточку.
5. В блоке **«Назначить исполнителя»** выберите, например, Анну, и нажмите
   «Назначить». Статус заявки станет **«Назначена»**.
6. Выйдите и войдите как исполнитель **Анна** (`anna@moebelstock24.de` /
   `worker123`). В «Мои задачи» видна только назначенная ей заявка (чужих нет).
7. Смените статус на **«Выполнено»**, добавьте комментарий/фото и сохраните.
8. Вернитесь в кабинет админа — статус заявки **«Выполнена»**, в карточке видны
   комментарий, фото результата и полная история изменений.
9. Проверьте изоляцию прав: под логином исполнителя откройте `/admin` — вас
   перенаправит обратно в кабинет исполнителя.

## Модель данных

- **User** — `id, name, email (логин), passwordHash, role (admin|worker), active`.
- **Request** — заявка: `id (= номер), clientName, clientContact, serviceType,
  description, address, preferredDate, photos, status
  (new|assigned|in_progress|done|cancelled), createdAt`.
- **Task** — назначение заявки исполнителю: `requestId, workerId, status,
  workerComment, resultPhotos`.
- **ActivityLog** — история: `requestId, actorId, action, note, createdAt`.

## Переход на PostgreSQL (для прода)

1. В `prisma/schema.prisma` поменяйте `provider = "sqlite"` на
   `provider = "postgresql"`.
2. В `.env` укажите `DATABASE_URL` для PostgreSQL.
3. Выполните `npx prisma migrate dev` (или `db push`) и `npm run db:seed`.

Модели и код приложения менять не нужно.

## Замечания по безопасности (MVP)

- Пароли хранятся только в виде bcrypt-хэша.
- Роли и владение задачами проверяются на сервере, не только в UI.
- Перед продакшеном замените `SESSION_SECRET` в `.env` на длинную случайную
  строку и включите HTTPS (куки сессии автоматически станут `Secure`).
